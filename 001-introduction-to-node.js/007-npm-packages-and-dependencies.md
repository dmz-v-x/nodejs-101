## npm Packages & Dependencies — How Reuse Works in Node.js

### 1. What is a “package”?

A **package** is:

- Reusable JavaScript code
- Written by someone else
- Published to the **npm registry**

Instead of writing everything from scratch, we **reuse packages**.

Common examples:

- `express` → server framework
- `lodash` → utility functions
- `chalk` → colored terminal output

👉 Modern development is built on **reusing packages**, not reinventing the wheel.

---

### 2. What is npm’s job?

**npm** is the **package manager** for Node.js.

npm does the following:

- Downloads packages
- Tracks versions
- Stores them on your machine
- Makes them available to your code

In short:

> npm manages packages for Node.js projects

---

### 3. Step 1 — Installing a package

Let’s install a package called **chalk**.

Run:

    npm install chalk

This command tells npm:

> “Download chalk and make it available to my project.”

---

### 4. What happens internally when you install a package?

When you run `npm install chalk`, npm does several things automatically:

1. Checks the internet (npm registry)
2. Downloads the chalk package  
3. Creates a `node_modules/` folder  
4. Saves the version in `package.json`  
5. Creates or updates `package-lock.json`  

All of this happens **without you doing anything manually**.

---

### 5. New thing #1 — `node_modules/`

After installation, you’ll see a folder called:

    node_modules/

This folder:

- Contains all installed packages
- Can become very large
- Is auto-generated by npm
- Should **never** be edited manually

👉 **You never commit `node_modules` to git**

---

### 6. New thing #2 — `package.json` update

Your `package.json` will now include:

    "dependencies": {
      "chalk": "^5.3.0"
    }

Meaning:

- Your project **depends on chalk**
- Chalk is required when your app runs

---

### 7. New thing #3 — `package-lock.json`

This file is extremely important.

`package-lock.json`:

- Locks **exact package versions**
- Ensures reproducible installs
- Guarantees everyone gets the same dependency tree

Rules:

- You do NOT edit it manually
- You DO commit it to git

---

### 8. Using the installed package

Create a file called:

    index.js

Write:

    import chalk from "chalk";

    console.log(chalk.green("Hello Node with Chalk"));

Run the file:

    node index.js

You’ll see **colored output** in the terminal.

That means:
- The package is installed
- Node can use it
- npm did its job

---

### 9. Key concept — `dependencies`

`dependencies` are:

- Packages required when your app **runs**
- Needed in production

Examples:

- express
- axios
- chalk

If your app cannot run without it → it’s a dependency.

---

### 10. Dev dependencies

Now install a dev dependency:

    npm install -D nodemon

This is the same as:

    npm install --save-dev nodemon

---

### 11. What is a dev dependency?

**Dev dependencies** are:

- Needed only during development
- NOT needed in production

Common examples:

- nodemon
- eslint
- prettier
- testing libraries

---

### 12. `package.json` after dev dependency

Now your `package.json` will look like:

    "dependencies": {
      "chalk": "^5.3.0"
    },
    "devDependencies": {
      "nodemon": "^3.0.0"
    }

Clear separation:
- `dependencies` → runtime
- `devDependencies` → development only

---

### 13. Why split dependencies and devDependencies?

In **production**:
- Only `dependencies` are installed

In **development**:
- Both are installed

This separation:

- Saves disk space
- Improves security
- Improves performance

---

### 14. Common beginner mistakes 

❌ Installing everything as a dependency  
❌ Editing `node_modules` manually  
❌ Deleting `package-lock.json`  
❌ Forgetting to install dependencies after cloning a project  

---

### 15. An experiment 

1. Delete the `node_modules` folder
2. Run:

    npm install

What happens?

💡 npm recreates **everything** using:
- `package.json`
- `package-lock.json`

This is HUGE.

It proves that:
- `node_modules` is disposable
- Your project is reproducible
- `package.json` + `package-lock.json` define your app

---

### 16. Final mental model

- Package = reusable JavaScript code
- npm = package manager
- `dependencies` = needed at runtime
- `devDependencies` = needed during development
- `node_modules` = generated, never committed
- `package-lock.json` = guarantees consistency
